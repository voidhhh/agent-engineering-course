# 考核方案

## 成绩构成

| 项目 | 比例 | 主要证据 |
|---|---:|---|
| 原理解构作业 | 15% | 分层图、时序图、边界说明 |
| 单元实验 | 30% | 代码、测试、成功/失败 Trace |
| 模块测验 | 10% | 概念辨析与机制推理 |
| 期中 Mini Harness | 20% | 运行时、审批、事件、恢复 |
| 期末横向评测 | 25% | 控制变量、数据、分析与答辩 |

## 实验评分量规

每个实验 100 分：

- 功能正确性 30；
- 失败路径和回归测试 20；
- 原理解释 20；
- 安全与权限边界 15；
- 可复现性和版本记录 10；
- 代码可读性 5。

## 期末项目最低要求

1. 至少比较三种运行实现，其中必须包含自制 Mini Harness；
2. 每种实现运行同一组不少于 30 个任务；
3. 记录模型、工具、Skill、超时、最大步数和审批配置；
4. 至少覆盖功能、注入、安全边界和恢复四类测试；
5. 提供原始轨迹、聚合结果和失败案例分析；
6. 不得把未控制的模型差异直接归因于 Harness。
7. 至少提交一个 DeepSeek 实际 API 案例的脱敏 Trace，并记录模型、thinking 配置、Token 与费用；
8. 同一案例必须有无需 API Key 即可复现的离线测试，不以在线服务可用性代替自动测试。

## 一票否决项

- 提交真实 API Key 或个人敏感数据；
- 删除、覆盖非实验目录数据；
- 伪造运行结果或删除失败样本；
- 未经说明更换模型、任务集或评分标准；
- 在公网暴露无认证的 Agent/Gateway。
