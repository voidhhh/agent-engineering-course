# 第 15 讲：DeepSeek Harness 与 Cordis

## 学习目标

理解“Everything is a Plugin”的组合方式，以及 Cordis 的 Service、Event、Effect 如何形成可替换、可回滚的运行结构。

## 1. 插件不是目录结构，而是生命周期契约

DeepSeek Harness 将模型、工具、上下文、权限钩子等能力组织为插件。关键问题是插件如何注册服务、订阅事件、声明依赖和释放资源。只有安装函数而没有清理函数的插件，会在热重载或测试中留下重复监听器与泄漏状态。

## 2. Cordis 三个核心概念

- **Service**：通过上下文提供的能力，消费者面向名称/类型依赖，而非硬编码实现。
- **Event**：生产者与消费者解耦的通知；顺序、错误传播与异步语义必须验证。
- **Effect**：带清理逻辑的副作用，使插件卸载时可撤销监听、定时器或注册项。

“可插拔”带来的代价是依赖图、初始化顺序和冲突解析变复杂。

## 3. 权限钩子

权限插件应收到规范化后的动作请求，在执行前返回可审计决定。策略需要依据工具、参数、调用者、Session、风险等级和已有审批，而不只匹配工具名。默认允许与默认拒绝的选择应由部署威胁模型决定。

## 4. 开发者预览的对待方式

若项目声明处于开发者预览或尚未完成安全审计，应把它当研究对象和实验运行时，而不是默认生产基座。固定提交、阅读变更、隔离凭据、限制工具，并在报告中明确不确定性。

## 5. 实验

实现一个 `greet` Tool Plugin 和一个权限 Hook：普通名字自动允许，包含外部发送意图的参数触发审批。安装、调用、卸载、重新安装各一次，验证 Service 与 Event 不重复。

### 验收标准

- 插件声明依赖和生命周期；
- Effect 清理后监听器数量回到初始值；
- 权限决定带策略版本与理由；
- 报告注明使用的仓库提交以及开发状态。
