# 第 7 讲：Agent Skills

## 学习目标

理解 Skill 的发现、触发、加载和资源组织，能够通过 Eval 改进触发准确率与任务质量。

## 1. Skill 是过程记忆

Tool 描述“能执行什么”，Skill 描述“完成一类任务时应该怎样组织步骤、证据和工具”。Skill 通常是包含 `SKILL.md` 的目录，可附带 scripts、references 和 assets。它不要求独立进程，也不是 MCP Server。

## 2. 渐进披露

Agent 初始只看到名称和描述；任务匹配后才加载完整 `SKILL.md`；更详细资料按需要读取。这种设计节约上下文，但使 `description` 成为关键路由器。描述既要写功能，也要写触发条件和边界。

## 3. 内容组织

`SKILL.md` 保留核心步骤和选择规则。长规范、schema 和例子放入 references；重复且要求确定性的操作放入 scripts；输出模板和素材放入 assets。一个 Skill 应聚焦一项可识别工作，避免“大而全”的领域百科。

## 4. Skill 与安全

Skill 可能指导 Agent 运行脚本或调用高风险工具，因此应被视为受信代码。来源、版本、依赖和允许工具应接受审查。Agent 自动修改 Skill 时需要版本历史、评测和可选审批，不能把一次成功经验直接提升为全局规则。

## 5. Skill Eval

至少测试两层：触发层测该触发时是否触发、不该触发时是否保持沉默；效果层比较有无 Skill 的任务成功、步骤、错误和成本。测试集应包含同义表达、边界任务和诱导误触发的反例。

## 实验

创建 `research-brief` Skill：要求明确问题、列出来源、区分事实与判断、给出不确定性。准备 10 个正例和 10 个反例，记录触发结果；再比较使用 Skill 前后的完整性和引用错误。
