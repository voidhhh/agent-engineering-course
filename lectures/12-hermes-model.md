# 第 12 讲：Hermes 模型与工具调用

## 学习目标

从模型层分析 Hermes 系列的指令遵循、推理与工具调用能力，并避免把模型与 Hermes Agent 运行时混为一谈。

## 1. 模型不等于 Agent

模型接收序列并产生序列；Agent Loop 解析工具调用、执行工具、回送结果并决定是否继续。即使模型经过工具调用训练，也不会自行拥有文件、网络或 shell 权限。权限来自 Harness 暴露的执行面。

## 2. 需要观察的接口契约

对任意 Hermes 模型，先确认模型卡与模板中的：system/user/assistant/tool 角色表示、工具定义注入方式、调用参数格式、并行调用支持、推理内容处理、停止标记和最大上下文。错误模板常比模型本身造成更大的格式失败。

## 3. 混合推理的工程影响

若模型支持可切换或可见推理，Harness 必须区分内部推理、用户可见文本和机器可执行调用。不要把推理文本当工具参数，也不要假定所有服务端都会返回同样字段。对比实验应分别报告任务正确率、调用格式正确率、步数、延迟与 Token 使用。

## 4. 公平比较

固定任务、工具模式、温度、最大输出、提示模板和 Harness，只替换模型；再固定模型，只替换 Harness。前一组回答模型差异，后一组回答运行时差异。若一次改变二者，结论不可归因。

## 5. 实验

选定一个明确版本的 Hermes 模型与一个基线模型，在相同的 10 个工具任务上运行。任务覆盖单调用、参数约束、连续调用、拒绝不存在工具和异常后修正。保存原始输出，不手工修复格式。

### 验收标准

- `baseline-lock.md` 记录模型标识、服务方式、模板与推理设置；
- 报告区分“答案错”“选错工具”“参数错”“协议解析错”；
- 不以一次展示案例代替统计；
- 所有模型使用同一工具实现和评分器。

## 6. 证据入口

以 Nous Research 的模型卡与 Hermes 官方仓库为准；社区帖子只能作为待验证线索。具体入口见 `references/official-reading-list.md`。
