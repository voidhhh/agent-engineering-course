# 第 11 讲：可靠性、安全与可观测性

## 学习目标

把失败、越权和恢复当作系统设计输入，并建立从事件到评测证据的闭环。

## 1. 威胁与故障模型

Agent 同时面对非恶意故障与对抗输入：模型可能选错工具；网络可能超时；工具可能部分成功；外部内容可能提示注入；用户可能请求越权动作；并发执行可能打乱结果。先列资产、信任边界、攻击者能力与失败后果，再选择控制。

## 2. 副作用分级

| 级别 | 示例 | 默认控制 |
|---|---|---|
| R0 只读 | 查询本地任务 | 自动允许、记录 |
| R1 可逆写 | 创建草稿 | 范围限制、幂等键 |
| R2 外部影响 | 发消息、提交工单 | 明确预览、逐次审批 |
| R3 高风险 | 删除、付款、权限变更 | 双重确认、强身份、独立策略 |

工具描述不是安全边界。执行前必须由可信代码校验身份、目标、参数、权限和审批绑定。

## 3. 恢复语义

超时并不代表未执行。对有副作用工具使用幂等键和查询状态接口；采用 `prepare/commit` 或草稿/发布两阶段；为不可恢复操作设置补偿流程。重试策略应依据错误类型，而非统一指数退避。

## 4. 结构化事件

最低事件集包括 run、model、policy、tool、state 五类生命周期事件。每条事件含运行 ID、会话 ID、事件类型、时间、因果父项、受控参数摘要、结果状态和版本。敏感值应脱敏，不能以“为了调试”为由进入日志。

可观测性回答“发生了什么”；Eval 回答“结果是否足够好”。没有事件，失败难以归因；没有 Eval，事件再完整也无法判断质量。

## 5. 实验：故障注入矩阵

注入工具超时、重复响应、未知工具、无效参数、审批拒绝、模型连续调用、Store 冲突和恶意资源文本。为每项记录预期状态、实际状态、是否产生副作用、恢复方式与证据事件。

### 验收标准

- 每种失败有确定的终态或暂停态；
- 未经审批的 R2/R3 动作执行数为零；
- 重试不会重复写入；
- Trace 能从最终结果回溯到模型决定和工具效果。
