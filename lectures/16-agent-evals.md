# 第 16 讲：Agent Eval 与课程收束

## 学习目标

建立覆盖结果、过程、安全、恢复和成本的评测体系，并用消融实验形成可复现结论。

## 1. Agent 不能只评最终文本

同一句正确答案可能来自可靠检索，也可能来自偶然猜测；任务失败可能源于模型、工具、Loop、上下文或策略。因此评测对象至少分为：任务结果、工具轨迹、策略合规、恢复行为、资源成本和用户交互。

## 2. 测试集结构

每个 Case 应包含输入、初始环境、允许工具、期望事实或不变量、禁止动作、预算和评分器。确定性约束用代码评分；语义质量可用带量表的人评或模型评分，但需抽样校准。安全 Case 重点验证“没有发生什么”。

## 3. 指标

- `Task Success Rate`：满足所有必要断言的比例；
- `Tool Precision`：有效调用占全部调用的比例；
- `Policy Violation Rate`：越权执行次数/风险机会数；
- `Recovery Rate`：注入故障后恢复到正确终态的比例；
- `Steps / Tokens / Latency / Cost`：效率指标，不能替代正确性；
- `Variance`：同 Case 多次运行的波动。

若满分为 100，课程建议综合分：

$$Score = 0.40F + 0.25S + 0.20R + 0.10O + 0.05E$$

其中 F 为功能，S 为安全，R 为恢复，O 为可观测性，E 为效率。任何高风险越权执行触发安全门槛，不应被平均分掩盖。

## 4. 控制变量与消融

先固定 Harness 比较模型，再固定模型比较 Harness。消融实验依次关闭 Skill、Memory、MCP、审批或上下文压缩，测量能力收益与风险成本。每次只改变一个主要因素并运行足够重复次数。

## 5. 实验与答辩

运行 `evals/` 的功能、安全和恢复任务；输出机器可读结果、原始 Trace、版本锁和报告。答辩时随机抽取一个失败 Case，现场从事件链定位责任层并提出最小修复。

### 验收标准

- 至少 30 个 Case，三类评测均有覆盖；
- 原始证据与汇总表可相互追溯；
- 结论包含置信区间或重复运行方差；
- 报告明确限制、失败样本与不可归因项。
