# 第 13 讲：Hermes Agent 运行时

## 学习目标

通过安装、轨迹和源码入口识别 Hermes Agent 的 Loop、Tool、Memory、Skill、MCP 与自我改进边界。

## 1. 解构顺序

先记录版本与默认配置，再从一个最小任务跟踪：输入如何进入、系统提示如何组装、模型如何请求工具、工具在哪里执行、结果如何写回、会话如何保存、何时加载 Skill。不要先从功能列表推断内部机制。

## 2. 自我改进的准确含义

Hermes Agent 所称的学习/自我改进，工程上主要体现为对 Skill、Memory 或工作区工件的创建和修改，并非运行过程中自动训练模型权重。必须分别审计“改了哪些文件”“为何被加载”“下次运行产生何种行为变化”。

## 3. Skill 与 Memory 的边界

Skill 是可复用的程序性工作流，Memory 是待召回的事实或经验；把每次结果都写成 Skill 会造成触发污染，把复杂流程只存为 Memory 又缺少可执行约束。二者的写入都需要来源、范围、验证和回滚。

## 4. MCP 与本地工具

MCP 扩展工具和资源边界，但不会自动提供最小权限。比较本地内建工具与 MCP 工具时，记录模式、认证、传输、审批、错误映射和运行位置。服务发现成功不等于调用安全。

## 5. 实验

在隔离目录运行官方 Hermes Agent 的固定版本，完成“读取三份本地资料、形成研究简报、保存一条经确认的规则”。导出完整轨迹和变更前后目录差异，然后关闭新写入的 Skill/Memory 重跑，观察差异。

### 验收标准

- 无真实账号、个人目录和生产凭据；
- 能指出 Loop、工具注册、Skill 加载和 Memory 写入的证据位置；
- 报告区分运行时事实、项目文档主张和本次实验观察；
- 所有持久变更可删除并验证回到基线。
