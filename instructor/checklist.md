# 教师备课与交付检查表

## 开课前

- [ ] 阅读 `COURSE_BASELINE.md` 并填写 `baseline-lock.md`；
- [ ] 运行 `pytest`、Ruff 和 `python scripts/validate_course.py`；
- [ ] 验证离线 Demo，无 Key 也能完成核心课程；
- [ ] 为平台实验准备隔离账号、目录和清理脚本；
- [ ] 检查所有官方链接与项目安全声明；
- [ ] 明确哪些实验会产生费用或外部副作用；
- [ ] DeepSeek Live 实验使用专用低额度 Key，确认 `.env` 未被跟踪并准备离线替代；
- [ ] 准备至少一个预期失败演示。

## 每讲

- [ ] 用一个可观察问题开场，不先给术语定义；
- [ ] 从消息、状态或调用轨迹展示机制；
- [ ] 让学生先预测失效结果，再运行注入；
- [ ] 验收机器证据，不只看截图和最终文字；
- [ ] 结束时要求写清责任层和未解决问题。

## 平台实验

- [ ] 固定 tag/commit 和安装日期；
- [ ] 不使用无版本 latest 得出比较结论；
- [ ] 区分官方事实、项目主张、课堂观察；
- [ ] 不挂载个人主目录或生产凭据；
- [ ] Live API Trace 已脱敏，记录模型、thinking、Token 和成本但不记录 Key；
- [ ] 课后确认后台进程、连接和测试数据已清理。

## 评分一致性

- [ ] 先用机器断言评分确定性指标；
- [ ] 人评匿名且使用统一量表；
- [ ] 保留失败 Case 和原始 Trace；
- [ ] 高风险越权使用安全门槛，不被平均分抵消；
- [ ] 抽查报告中的版本、汇总和证据可互相追溯。
